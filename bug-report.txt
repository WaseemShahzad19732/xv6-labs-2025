Bug: Uninitialized pages leak cross-process memory

Description:
In the syscall lab, xv6 disables memset() calls that zero newly
allocated user pages (in uvmalloc) and poison freed pages (in kfree)
when LAB_SYSCALL is defined. This causes sbrk() to return pages
containing leftover data from previous processes.

Impact:
Breaks process isolation. An attacker can scan pages from sbrk()
to recover secrets (e.g., from secret.c), as demonstrated by attack.c.

Proof of Concept:
- Run: secret xyzzy
- Run: attack
- Output: xyzzy

This is a real-world vulnerability class (e.g., Linux CVE-2017-17053).

Suggested Fix:
Re-enable the memset() calls to zero user pages before allocation.
